# v0.18.340 — source-proof model publication and bounded evidence-saturation completion

## Root cause from the actual v0.18.339 read-only trace
The user reported a **51.152-second** read-only single-device connectivity investigation: **11 Ollama Cloud Gemma 4 rounds**, **9 tool calls**, **45.291 seconds provider** and still the deterministic 48-hour device-status report. The private provenance signals showed the first no-tools draft was unchanged through the coordinator/author step, but the incoming API-boundary message differed. The prior v0.18.339 claim gate required four-way literal equality (first model -> coordinator -> author -> *API incoming*), which can veto a perfectly valid typed claim plan after an independent host-side calibration. Also, **four separate retry systems** could independently request more source reads after adequate bounded status/history/log evidence, while the published root-cause verdict remained unverified.

## Architecture changes
- The publisher no longer confuses host-side API message modifications with invalid source claims. It requires **raw-first no-tools draft == coordinator result == author answer**, then **independently re-attests the original two-field JSON claim plan** against final normalized source records. An outer confidence/coverage adjustment no longer prevents a valid model-selected claim plan from producing a source-rendered public answer. Arbitrary model prose remains forbidden; source claims, target identity, clock conflict, material uncertainty and no-controls rules remain mandatory.
- Rejecting a plan now records a **fixed allowlisted diagnostic reason** (`answerPublicationDecision.modelClaimPlanRejection`), without any private text, IDs or credentials. This distinguishes no raw draft, intervening repair, missing source, non-JSON model reply and missing mandatory uncertainty. The formatted result still comes from host source facts only; no claim of natural-language semantic attestation.
- The eligible final synthesis task now explicitly requires **strict two-key JSON plan format** rather than describing it as optional. There are no extra model calls.
- Introduce `telemetry_completion_policy.py`: a single status/history/source-log target plus **one discriminating read** (such as target driver configuration or verified dependent-app settings) or a previously offered targeted evidence-gap checkpoint is enough to stop launching other retry subloops. The existing final no-tools model synthesis and independent source publisher remain in charge; **root cause still unresolved** if driver/upstream proof is unavailable.
- Limit the single-device read-only connectivity planning loop to **six** tool-choice rounds at most. This does not alter other domains, write/confirmation routes, or explicit comparative/home-wide requests. Record `telemetry_read_round_budget` and `telemetry_sufficiency_stop` privacy-safe counters. This caps wasted rounds rather than pretending new evidence exists.
- No home-system, rule, device or automation write. No speculative MQTT physical diagnosis.

## Acceptance and limits
Tests cover (a) source-valid model claim surviving a **different incoming message**; (b) false free-form prose rejected with fixed reason; (c) anti-leak model draft boundaries; (d) exact-ID, single-device source saturation and fake/missing log, app, identity and cross-domain negative controls. Full release, smoke, metadata, scorecard and Python CI required at exact PR head.

This is a significant **general architectural convergence** on typed source-proof plans, not a final certificate of Claude-like open-ended reasoning. Lighting, heating and semantic entailment of unrestricted model-authored prose remain fail-closed; first-response accuracy, first-attempt plan adherence, source quality and speed gains remain **NOT MEASURED** without the next live run. The v0.18.339 and v0.18.340 source windows differ and must not be treated as a controlled A/B. Stronger semantic causal claims still require independently attested source witnesses.

## Rollback
Revert the original-draft claim gate adjustment and unified telemetry completion calls, preserving the v0.18.339 source-first fallback; version and tests revert together.
