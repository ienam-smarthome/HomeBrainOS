# HomeBrainOS v0.18.362 — installed Rule Machine writer contract preflight

## Real confirmed write failure (2026-11-02)
A user asked HomeBrain v0.18.361 to create a **one-time native Rule Machine** rule for an existing Internet-control switch, confirmed the action, and received `Unknown hub_set_rule property`. The first read-only preflight correctly resolved the Internet control (ID 6923) and found 41 existing rules. After user approval, HomeBrain submitted a legacy direct shortcut payload `hub_manage_rule_machine(tool=hub_set_rule, args={name,addTrigger,addAction,confirm:true})` to Hubitat. The gateway rejected it in approximately 125ms and returned no rule `appId`. The record documents an unsuccessful/NOT VERIFIED create, **not independent proof that no partial state exists**. Check current rule inventory before any subsequent manual attempt. The proposed one-time 2026-11-02 15:35 trigger must not be blindly retried after its scheduled instant has passed.

## Confirmed cross-project cause
The installed/upstream Hubitat MCP Rule Server changed `hub_set_rule` from the older shortcut authoring contract to a **native Rule Machine document/form contract**. The upstream `libraries/mcp-native-documents-lib.groovy` `toolSetRule` checks the exact top-level set `operation,rule_id,args,confirm,bestPracticeKey` and throws the *same error string* `Unknown hub_set_rule property` for `name` and `addTrigger`/ `addAction` at that level. Current native creation uses `operation='create'` with `args.parent_id`, `args.name`, and `args.changes=[{part,value},...]`, with native typed trigger/action field IDs and `confirm=true`. Blindly moving or renaming shortcut keys is **not a correct/native rule writer**. The installed server's actual guide remains the authority; upstream source establishes likely version family but no actual installed hub version was independently read.

## Minimal general safety fix
New `rule_writer_contract.py` classifies only a **read-only source guide** `hub_get_tool_guide(section='set_rule_reference')`: legacy shortcut, modern document writer, or unknown. `RuleAuthoringService.propose` now checks this contract **before** device resolution/confirmation. For new or unverifiable contracts it returns an explicit, safe unavailability explanation and queues **no rule write**. During confirmed Rule Machine create-group preflight, it checks the current installed contract again, before any gateway mutation, preventing a queued legacy create from being replayed after an MCP server upgrade. Existing duplicate-name and device-command checks continue under a positively verified legacy guide. The guide text is never inserted in user Technical JSON: only a short contract-classification evidence receipt is recorded. The system does not claim to support modern native writing, silently substitute Visual Rules, bypass approval or schedule a new event time.

## Limitations and next milestone
**This is a fail-safe compatibility fix, NOT a working native-document Rule Machine compiler.** A follow-on must discover a real native Rule Machine parent ID, live typed trigger/action field IDs and supported change order through the installed **read-only** guide and native schema/form exploration, build a separately tested native-document compiler, retain confirmation/backup/duplicate/time-expiry protections, and verify the final rule's trigger/action/readback. Do not guess inputs or test with a live write absent explicit user approval.

The user should be told that the original rule was not verified and should inspect exact-name Rule Machine rules for partial creation. The original time-specific request must be re-asked/reconfirmed with a future time before any eventual creation; an old confirmation is not permission to write a new schedule.

Synthetic offline tests cover the new/legacy/unknown guide classification, modern contract refusal before any device or write call, unavailable guide fail-closed, confirmation replay revalidation, legacy duplicate preflight, and privacy. **Actual live v0.18.362 installed behavior NOT MEASURED** and no native-rule writing success is claimed. No Hubitat/HA writes, automations or device settings were changed by development.

## Rollback
Revert this PR if guide compatibility is misclassified or legacy installed servers are unnecessarily blocked. Never disable verification or retry the old payload against a modern document API merely to avoid a confirmation failure.
