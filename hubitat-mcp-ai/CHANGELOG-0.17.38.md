## Reusable architecture changes

1. **Investigation intent outranks snapshot shortcuts** in the production agent.
   Recognised analytic goals pass to the bounded evidence-planning pipeline.
   Configuration-only app inspections remain fast and deterministic.
2. **Shared Rule Machine request parsing** distinguishes an ordinary current
   configuration review from a history/causal execution question. A named app
   ID alone is not evidence that a current snapshot answers the objective.
3. **Stable device identity** supports unique display-decorated labels (e.g.
   dynamic light status shown in parentheses), while refusing collisions.
   The historical motion lockout collector can therefore look up the same
   physical light referenced without its status suffix.
4. **Local history receipts are first-class evidence.** The same coverage
   assessor now recognises the native `homebrain_device_history` source as
   it does remote MCP gateway subtools. Derived staleness counters support
   stale-reporting diagnosis, not proof of device command reachability.
5. **Regression fixtures** exercise the actual 0.17.37 historical lockout
   wording, explicit current-configuration questions, duplicate aliases
   and Bedroom 3 Mesh stale telemetry evidence.

## Safety and remaining limitations

Read-only. No device commands, new background reads, automation changes or
Historical Journal configuration changes (still 7 days / 200,000 rows).
The scheduler improvements already confirmed in 0.17.37 are preserved.

The historical lockout collector must still be verified live. A retrieved
OFF edge, button press and motion sequence alone cannot prove app 4019
engaged its lockout; a contemporaneous decision/execution source is
necessary. Device-age counters are generated by the hub and must not be
mistaken for new inbound device telemetry.
