# Hubitat MCP AI v0.18.215 — Model-authored natural explanations with independent factual gates

## Live V2 review, 29 October 2026

The v0.18.214 broad health test recovered 11/11 successful reads in 33.947 seconds, joined three independently matching source cases, and placed Bedroom 3 Mesh (29 sampled WARNs, healthStatus=offline), Matter Zemismart M1 Bridge (10 sampled WARNs, healthStatus=online but networkStatus=offline), and SenseCap D1 Settings (37 sampled WARNs) ahead of stale-only device counts. Its final claim-selection model output was unusable (`non_structured_answer`), but the host used a correct, static source-connected summary (`concise_answer_source=cross_source_verified_case_graph`). It still lacked a naturally worded evidence-based explanation of why these observations merit checks, and useful next read-only diagnostic actions. Other diagnostics show 51 stale device entries, but staleness alone proves no offline connectivity; the two MCP Rule Server errors were tool-input validation errors rather than confirmed physical faults.

## Architecture change

- Add `native_verified_prose.py`, an **independent, fail-closed** verifier for bounded, model-authored narrative findings anchored to the exact source cases recovered by successful MCP reads.
- A narrative item has exact `source_id`, a model-written `explanation`, and a model-written `next_check`. The host checks membership in independently returned source cases, matching source name/ID, exact warning counts and severity, equality of reported status-field values, numeric provenance, limited source-neutral vocabulary and absence of unsupported causal/physical-fault assertions. Next checks are allowed only as non-executing diagnostic recommendations. Entire proposals with unsupported content are rejected without publishing partial model prose. No user/model text is source authority.
- Only the **explicitly opted-in Native V2 API path** enables one extra optional, bounded tools-free model explanation call. The pre-existing model-controlled MCP READ execution, operation effects, identities, read budgets and write protections are unchanged. The call runs when a broad non-targeted investigation has a linked-source case and at least 7.5 seconds of total budget left; its maximum duration is 6 seconds. A rejected, empty or unavailable model explanation falls back to the identical host-verified v0.18.214 answer.
- Preserve full technical claim ledger/verification report unchanged. Diagnostic fields disclose `verified_narrative_accepted`, `verified_narrative_result`, `verified_narrative_ms`, and `concise_answer_source=model_authored_independently_checked` only when truly accepted. Model-only time is measured separately from tool reads and earlier claim-selection time.
- Regression tests cover natural-language acceptance with conflicting statuses and source counts, unknown/mismatched IDs, fabricated numbers, severity mismatches, unqualified offline claims, unsupported physical/causal claims, injected URLs, unsafe modification recommendations, complete Native V2 tool-flow integration, fallback, and opt-out compatibility.

## Important limitations

This is the first **constrained natural-language explanation** pass, not general free-form factual entailment. Deterministic source-token verification cannot safely certify arbitrary claims, so unknown model vocabulary and semantic assertions are rejected in favour of the existing host account. Model-authored recommendations are **suggestions only**, never executed, and source observation does not prove a physical failure, working automation or actual causal mechanism. This extra call can increase latency up to six seconds; it must be weighed against answer usefulness using side-by-side live V1/V2 runs. Single-device causal incident reports keep their existing source-authoritative path; the new pass does not replace them.

No Hubitat write operation, Main Ask control action, repository credential, device rule or automation is changed.
