## Architecture improvement

- **Separate investigation from publication authority.** The LLM still freely chooses available authenticated read-only MCP tools and interprets sources during investigation. For any **source-classified generic device excessive-hub-load incident** whose causal attribution is unverified, the user-visible causal conclusion is now reconstructed from a fixed, source-receipt-backed incident packet *regardless of the model's exact wording*. The unverified free-form narrative is withheld; model interpretation remains used for investigation. There is no new user-question keyword route, hard-coded device ID, or automatic gateway read.
- **Evidence claim ledger (first stage).** The new bounded deterministic ledger distinguishes source-verified generic WARN observations, independently verified issuing-app IDs, bounded event-history command overlap, time-associated device event observations, and the **unverified root cause**. Each fact records specific READ receipt numbers and source coverage limits; unsupported model claims are not represented as verified.
- **Conservative causal presentation.** Reports incident times, verified caller names/IDs, recorded command bursts and their gap from the warning, and timestamp-nearby device-owned *source-reported* state changes, but never ranks which caused hub load without independent runtime evidence. Missing history is explicitly not evidence of absence.
- **Narrow source classification.** Only actual excessive hub-load message types trigger this source authority. An unrelated device/watchdog WARN remains on the existing native model route. This is a log-source classification, not word-routing of the user's question.
- **Audit diagnostics.** Adds incident_claim_ledger, model_narrative_withheld_for_unattributed_incident and final_synthesis=source_bound_unattributed_incident; retains the old heuristic flag only as a diagnostic, not a gate. No auto-fixes, tool permission changes or production Main Ask modifications.

## Limitations and next stage

The claim ledger currently independently verifies **only** fixed factual evidence categories around a source-classified generic high-load WARN; it is not a full semantic verification engine for arbitrary model statements, other incident types or driver execution paths. Existing timezone comparisons are made using unzoned printed source timestamps; the ledger never treats them as guaranteed aligned. The projection can omit event history, so a zero observed command count is bounded evidence rather than proof of no command. Determining the actual callback / network / CPU cause still requires a separate, independently verified driver-source/runtime profile. The stronger boundary intentionally withholds even well-worded free-form model summaries until their claims can be independently attested. Future development should integrate structured claim objects and source-receipt citations for broader question types and relax the boundary only when those structured claims pass validation.

Experimental V2 remains strictly READ-only. No Hubitat devices, rules or apps were modified.
