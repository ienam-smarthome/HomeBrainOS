# v0.18.339 — model-directed, source-attested answer claims and scoped-read repair

## Evidence from live v0.18.338
A read-only Bedroom 3 Mesh investigation took **130.628 s** (11 Ollama Cloud rounds, 10 recorded tool calls), with **74.284 s** spent on an unscoped 207-device `hub_list_devices` read and an associated broad `homebrain_filter_devices(deviceHealth=stale)` call. It ended with a deterministic telemetry explanation. True first no-tools synthesis was now correctly captured: `firstNoToolsDraftCaptured=true`, `draftUnchangedAtCoordinator=true`, `coordinatorUnchangedAtAuthorBoundary=true`, `authorAnswerUnchangedAtSharedBoundary=false`. **The model's unrepaired answer was replaced despite the extra source reads.** This is an uncontrolled run; no causal claims of performance improvement are established.

## Model-directed publication architecture
- New `proof_carrying_answer.py` independently constructs a bounded, typed, source-checked claim set from the **single target's** normalized Hubitat state/history, with cautious read-only caveats, last event and conflicting driver clocks. It rejects missing IDs, non-targeted sources, commands, truncated/ambiguous events, suspicious input strings and root-cause-verified mismatches.
- The existing final no-tools synthesis optionally receives a **schema-constrained claim-ID planning prompt** for exactly this narrow status case, without another model/MCP round. This lets the model choose and order which independently verified statements answer the question. A candidate must be valid JSON with a closed schema, a bounded nonrepeated claim list, all material status/conflict/cause-gap obligations and no arbitrary prose.
- The shared answer boundary independently **rebuilds the claim set** and only admits the model-selected plan when the authentic first no-tools draft exactly equals the coordinator result, author-guarded result and incoming answer. The public result uses source-certified host text for *every sentence*. This is a safe, **model-directed answer plan**, **NOT unrestricted model-authored prose**. That semantic distinction matters: neither model-written citations nor arbitrary sentences can independently prove their own causal meaning.
- Unadmitted candidates, changed or repaired model drafts, detailed incidents, commands/truncation, ambiguous identity, other domains (including lighting and heating) and any write intent retain existing guards and source-based fallback. Expose `answerPublicationDecision.mode=model-directed-source-claims`, `modelChosenClaimsAttested=true`, `modelProseCertified=false` only for admitted plans.
- Repair hidden expensive broad reads: a single-device `homebrain_filter_devices` operation can trigger a nested unscoped Hubitat inventory call; block non-target attribute filters after source-verified single-target resolution instead of guarding only unrelated name filters. Explicit whole-home comparisons remain permitted.
- No new provider/MCP calls, writes, command permissions or settings changes.

## Regression and next milestone
Full and dedicated CI must test: positive model-selected source-plan admission, invalid/free-form/extra/hallucinated facts, duplicate/unknown claim IDs, mandatory uncertainty/clock mismatch, modified model outputs, API privacy and cross-domain/write fail-closed. One live status case does not prove general Claude-level quality or lower latency. The official 31-case quality scorecard remains **NOT MEASURED**. Future work requires richer typed proof adapters (lighting and heating), and an independently validated **semantic prose entailment** strategy before allowing the model to write free-form causal paragraphs. Do not extend a lexical whitelist or promote a source-checked category to a physical-cause proof.

## Rollback
Revert the narrow optional prompt and finaliser admission to restore deterministic source-only publishing. Remove the attribute-filter admission change separately to restore prior read breadth.
