## General cause and minimal fix
`requested_event_window_evidence.render_requested_event_window_evidence` previously required `details.observedEvents` to be a list, even for a **successful explicit-zero** `homebrain_device_history` result whose device-history service intentionally omits this field. It returned `None`, skipping the source-timed final model packet entirely. A successful, typed, read-only receipt with **integer** `sourceEventCount=0` and **integer** `analysisEventCount=0` now permits an empty bounded event list if `observedEvents` is absent. Existing user-relative window logic, source success/effect/evidence-kind gates, exact source attribute/label checks, integrity caveats, and model-authored prose remain unchanged.

Do **not** interpret missing `observedEvents` as zero when the source/analysis count is absent, malformed or nonzero. An explicit empty list paired with conflicting nonzero reported counts is also rejected. This is receipt integrity preservation, **not a new completeness claim**. The final timing packet continues to say that no records in the bounded returned source is not proof of no physical detection, no automation commands elsewhere or no dropped events.
