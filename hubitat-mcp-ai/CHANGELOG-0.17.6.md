# 0.17.6 — Skill-guided, live-catalog MCP reasoning

HomeBrain has historically accrued domain-specific investigation and presentation patches. The attached Claude Hubitat MCP skill identifies the missing reusable architecture: progressive discovery from the **live server**, tool-guide-assisted operation selection, evidence-led investigation, and explicit safety boundaries.

## Runtime architecture

- A reusable `mcp_skill_guidance` contract informs the model about on-demand capability discovery, multi-stage evidence questions, read/write split, native Rule Machine and classic app handling, and outcome verification. It is generated by broad domain, not one function per device/question. The live server's schemas and `hub_get_tool_guide` override potentially stale skill descriptions.
- All currently advertised MCP functions are kept in the request's **available** registry. The prior `[:tool_limit]` slice is removed; model-visible tools remain compact and selectively declared, so this does **not** mean a giant model schema dump.
- Exact-operation searches (`hub_get_app_config`, `hub_list_rules`, etc.) prioritize matching live search rows even when fuzzy results rank the correct gateway below the usual top-two cap. Unrelated gateways are not exposed by an exact lookup.
- Explicit **deep/thorough/investigate/analyse/diagnose** causal questions use the verified deterministic event baseline, then enter the model's tool-reasoning loop instead of always short-circuiting when a command producer is known. Ordinary concise causal questions retain the existing fast, provenance-grounded reply.
- Deep investigations have a bounded 18-read, seven-tool-round profile. Ordinary and investigative profiles retain their existing limits. Installed read-only app/rule/log gateways can be exposed during a deep follow-up, subject to the live MCP registry and declared-tool limit.
- Device controls and sensitive/destructive writes still pass the existing effect classification, identity, confirmation and MCP permission gates; the skill prompt is not an enforcement mechanism.

## Testing

Contract regressions verify skill guidance, exact tool discovery beyond fuzzy rank two, an installed gateway beyond the former 48-list truncation, live read-only gateway declaration, unchanged normal fast-path behavior, and model continuation for an explicitly deep causal investigation.

## Limits

This is the first reusable architecture step, not a guarantee that any local model will perform identically to Claude or that all MCP tools work in a particular user's installed server. Broader generalized evidence graphs, automatic sufficiency scoring, ongoing evaluation across many questions, model tool-call compatibility and live-device integration tests remain future work.
