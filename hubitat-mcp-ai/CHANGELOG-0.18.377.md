# v0.18.377 — safe one-time schedule boundaries (native writer still disabled)

## User problem and verified repository facts

A timed Internet-control request currently routes correctly to the deterministic Rule Machine authoring service and resolves Internet-room Switch targets with **off = blocked** and **on = allowed**. However, its live writer compiles retired `addTrigger`/`addAction` shortcuts. The installed newer server advertises native `hub_set_rule(operation="create", args={parent_id,name,changes}, ...)`; `rule_writer_contract.py` already safely stops the incompatible write. An independent offline native one-time compiler and native-parent source projection exist, but neither is a complete enabled writer. The native *date value* key/format and successful one-time create/readback have not been verified on the user's hub. No truthful code-only change can assert that "block after 15 minutes" is now executable on that server.

## General fixes in this release

- Native one-time request on a native-document server now returns **`native_oneshot_date_field_unverified`**, not just the vague "Couldn't schedule". Native recurring requests still refuse separately with **`rm_contract_changed`**. The current write/confirmation action list is empty, no Hubitat creation or device command is performed.
- Added **read-only** typed-settings differential inspector. With a real date-checked `Certain Time (and optional date)` rule and a separate undated one, it returns a candidate date selector only if the same trigger type, explicit `date1=true`/baseline false, exact `YYYY-MM-DD` value and a unique typed suffix-1 field are all present. Duplicates, redacted/wrong-field values, changed trigger mode, same rule ID, missing/invalid dates reject with `native_oneshot_date_field_unverified`. The result never proves form placeholder semantics or execution. `NATIVE_ONESHOT_ENABLED=False` and the offline compiler `write_ready=False` remain.
- Relative delays now add **elapsed UTC minutes** for aware datetimes and **round UP** to a whole minute. This prevents firing before a requested delay, including near midnight and a spring DST transition. One-time authoring refuses a past/within-60-second wall time or a DST gap/repeated wall hour; no guessed offsets.
- Newly generated one-time labels include the exact **`HB one-shot |`** prefix. The existing daily cleanup now requires **both** that prefix and the dated `(One-time YYYY-MM-DD HH:MM)` suffix before any destructive candidate selection. **Existing legacy suffix-only rules will no longer be automatically deleted**; review them manually if necessary. The new prefix is a narrow naming convention, *not cryptographic proof of ownership or device-effect verification*. The cleanup still has its pre-existing runtime config and uses the existing Hubitat soft-delete gateway; this release does not implement a new backup, pause or actual state readback lifecycle.

## Test and acceptance boundary

Offline regression tests exercise date field discrimination with **synthetic** samples, wrong or missing fields and duplicate dates, midnight/DST and past/too-soon timing, and prefix-only cleanup. Existing read-only device identity resolution, native guide incompatibility, confirmation and duplicate-rule checks remain unchanged. Full exact-head CI is required. No live MCP/Hubitat/HA writes, no Cloud inference use or add-on setting changes.

**Expected effect:** a clear refusal code instead of a misleading schedule success, accurate one-time clocks, and lower risk of automatically deleting user-created suffix-only rules. **Actual delayed Internet block on the installed native server remains UNAVAILABLE / NOT VERIFIED** until an explicit user-approved throwaway probe supplies the real dated settings; then a separate safe native writer + backup, duplicate/reconciliation, confirmation, create-readback and after-fire verification must be implemented and tested. Do not automate a probe rule creation/deletion without new, explicit consent. Do not assume the `hub_set_rule` read route or guide accepts any schema not actually returned.

**Rollback:** revert this release's authoring refusal/timing/ownership behavior and date differential utility. The old cleanup name policy is less conservative and should not be restored without reviewing the destructive matching risk. Legacy suffix-only one-shots may need manual review.

**Formal quality/performance:** native writer live after-result NOT MEASURED; no claim of fixing scheduling success, no first-answer/model A/B gain established. The Q0–Q4 Answer Quality charter remains active.
