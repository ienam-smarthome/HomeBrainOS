# HomeBrainOS v0.18.199 — independently attested static Groovy method paths

## Trigger: v0.18.198 live verification (29 October)

Google Nest Hub (7934) gave 3 generic high-load WARN rows at 19:55:19 and independently verified calling apps 1679 and 4080, but no app-issued command in the five-minute printed warning window. The separate 11-refresh Adhan Player burst was ~100 minutes earlier. Native V2 safely declined to rank a cause, but 11 attempted reads included redundant logs and produced no verified driver implementation evidence. The incident-time execution path, network latency and CPU contribution remain unknown.

## Architecture change

- **Static execution-path index, not a guessed cause.** After a model-chosen authenticated `hub_get_source` READ yields complete, contiguous, identity-matched Groovy, locally parse method boundaries and produce a bounded, redacted lexical method-call map. Report direct references to other declared methods and an explicit allowlist of Hubitat network, schedule and event APIs. No code, literal, argument or private value is returned to the model.
- **Follow verified warning methods.** Source-attested, named-method WARNs (e.g. `runQ`, `setVolume`) can prioritise relevant definitions and their direct static links. This does not presume the WARN corresponds to an app command or that a particular branch executed.
- **Fail closed.** Source-read success without code, missing source response identity, app-versus-driver type mismatch, truncated content, mismatched length, uncertain lexical body, or dynamic dispatch cannot authorise a confirmed execution-path claim. The host does not fetch source automatically.
- **Independent evidence receipts.** Read IDs and structural path summary are preserved for further native model examination and focused synthesis. The investigative system prompt now asks for competing-hypothesis testing rather than following a purported offender.
- **Regression tests.** Synthetic full/partial source, app-versus-driver collision, missing ID, unbalanced methods, comments/strings, privacy protection and allowed platform calls. Production Main Ask unchanged.

## Boundaries / next development

This stage produces a **static structural hypothesis** only when a gateway actually returns complete code; the current Google Nest Hub gateway response may supply metadata without source, so live root cause is *not yet solved*. The method graph is incomplete for dynamic Groovy dispatch, closures, inheritance, event subscription and platform callback scheduling. A profile that measures actual execution around a warning is still necessary for runtime causality.

Next: test the new source contract live; then extend source-attested claim ledgers beyond generic warnings and build model-directed discriminating follow-ups (not keyword-specific routes). Experimental Native V2 remains READ-only, with no Hubitat app, rule or device writes.
