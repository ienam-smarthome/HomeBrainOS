# HomeBrainOS V2 alpha.139 — event-time causal source sufficiency

**Status:** [PR #1715](https://github.com/ienam-smarthome/HomeBrainOS/pull/1715) merged as `cc4bdf6b35ff0bd924fc366e4f0ac3224d4f134e`, with **all 5/5 exact-head CI workflows passing**. Fresh installed source-real first-answer acceptance is still pending.

## Motivation: source-real alpha.138 benchmark

The uncoached private installed alpha.138 read-only WHY capture (2/8 human first-answer review) correctly retrieved the shared output's operating history and scheduler-produced setpoint events but *incorrectly* attributed the historical initiating demand to the controller/output itself. The current installed controller configuration explicitly distinguished a multi-input/room demand strategy from the selected shared output/master device. A later current temperature was projected back into a historic decision, while **no original event-time controller execution-log receipt** was read. A final causal publication check returned **passed** despite the definite assertion; the new alpha.138 evidence-preserving source-only fallback did not run. Owner-supplied separate historical controller logs identify the actual earlier demand, but do **not** count as receipts fetched by alpha.138. No private app/room/device logs are committed.

## General model-led, cross-domain correction

- Extend the **existing** `causal_claim_publication.py` with a bounded **original source-category** index counting successful current device inventories, installed app configuration pages, validated device histories, state observations, recorded native command rows and command issuers, and originally retrieved app-scoped past logs. A positive category is **not** proof of event-specific controller decision, upstream input or physical effect. A configured master/output is **not** necessarily the demand/input source.
- Deliver this compact, input-neutral distinction to the model in the **existing** causal source review and final textual audit. No source/tool/action/device or causal answer is preselected; only the model can decide a proportionate read if available, or abstain and retain verified observations. No additional host-dispatched call or model round.
- Extend the conservative publication floor to catch **definite event-time triggering assertions** phrased without `because`, including threshold-to-action statements and active/passive causation language. If no appropriately related original execution source category was read, fail closed to the pre-existing evidence-tiered source-only partial renderer. Current configuration, later device snapshots, notified listeners and source catalogs cannot fill that evidence gap. The safe partial preserves original bounded device and app-log evidence where available, not the rejected prose.
- The guard's execution-source category remains necessary but not sufficient: even a nonempty related app log is not automatically proof of a specific decision or physical effect. Retain the original no-claim/no-action pathways, native write safety, approvals, V1, scheduler code, provider routing, and unchanged full original receipts.
- Fictional cross-domain tests exercise the exact previously escaped causal phrasing, unrelated/failed app logs, command issuer versus upstream trigger, current state/config category distinctions, output-only vs input roles, original event-time source index in the existing review, no new writer, and safe partial output.

## Acceptance and limitations

Require all exact-final-head CI workflows (V2 pilot, full release assurance, repo validation, scorecard integrity and UI fixture screenshots), then an uncoached fresh installed alpha.139 source-real first-answer benchmark in multiple device domains, scored under the permanent 53-case roadmap. Specifically compare event-time input/decision evidence, role of controlled output versus participants, producer versus issuer/listener, timestamp chronology and lookback caps, source completeness, final publication result, and model/token/wall-clock cost. No single previous benchmark, synthetic suite or success-shaped status proves improved live causal reasoning. An unnecessary overbroad rejection or a convincing incorrect cause is a live failure. Rollback to alpha.138 requires no migration.
