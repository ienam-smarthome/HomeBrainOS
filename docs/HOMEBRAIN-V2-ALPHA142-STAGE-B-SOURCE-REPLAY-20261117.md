## Bounded Stage B design

- New pure `causal_stage_b_frontier.py` indexes **original full source receipts** (up to 40, 250 events each and 700 inventory devices) rather than the model's compacted 21-KB inventory display. Every candidate is grounded in a valid native event-history identity and date or actual returned current-state capability; source and read-only live catalog fields are checked.
- **Causal reads ranked**: (1) same-output, previously unqueried *unfiltered* command/other-attribute history; (2) app-scoped event-time logs for a recorded native command issuer (if one is actually found); (3) app-scoped logs for event-notified listeners **explicitly marked not issuer or input-decision proof**. Source IDs from `triggered[]` are not turned into recorded command issuers or an assumed controller. A failed or zero-result broad log is never proof of no execution.
- **Outcome scope candidates separate from causal candidates**: devices from the full successful original inventory with the same observed reported-state attribute under `currentStates`, never from an arbitrary shared Hubitat room. A capability match only identifies a device worth assessing for latest-event scope; it cannot establish a historical demand or that the device was heating. A generic question about "heating" might refer to the shared boiler call or individual TRVs and must label the distinction.
- **Conservative retention**: classify `outside_retention_source_explicit` *only* if an original native past-log response explicitly supplies a trustworthy timezone-aware `oldestRetainedTimestamp` after the relevant event. A global `total`, oldest row returned by a limited query, a zero-match `matched` count or an old separate pasted excerpt does **not** prove retention or absence; mark `empty_result_scope_or_retention_unknown`. Where explicit retention makes logs futile, suppress app-scoped proposals without suppressing native event-history opportunities.
- **Model-owned runtime**: V2's existing causal review and one follow-through round receive the ranked, source-bound read-only options. Only if an original, successful broad past-log read returned zero matches, eligible original listener IDs and a truly advertised app-scoped tool exist, a **single** extra model-owned recovery checkpoint is possible *before* the final tool-free claim audit. Neither this module nor the host automatically selects a tool or cause.
- **Hard recovery caps**: 2 native Stage B recovery reads total, at most 2 app-scoped reads, source-bound target ID, bounded incident time, and no unscoped repeated log or native writes. Existing request timeout, catalogue/argument checks and explicit no-further-read prohibitions remain. Model may decline. This limit is Stage B-specific; the preexisting general investigation has its own model/tool limits unchanged.
- **Cost/quality telemetry**: private Technical JSON now reports Stage B invocation and attempted source reads, alongside existing model rounds, token counts, per-read elapsed times, final-audit outcome and causal publication status. If Stage B is invoked but an explicit initiating-actor question still fails the source floor, skip a redundant, tool-free model audit and let the existing original-receipt publication floor return a bounded answer.
- V1, thermostat scheduler, native action/writer approval, provider routing, original receipts and permanent 53-case benchmark stay unchanged.

## Offline and live acceptance criteria

**Offline original-shape replay:** 201-item source inventory + filtered main-output states + original empty broad log; top-ranked next read must be **same-device unfiltered**. Relevant input-app reads rank after a recorded command issuer, or as explicitly unverified notified-listener candidates. Calculate independently declared `precision@3`, `first_useful_rank` and `useful_read_rate`; source expectations do not enter the frontier itself. Confirm source-ID and window validation, never authorize writer, identical-read suppression, and full-inventory capability-based scope without room inference.

**Negative controls:** cross-domain lighting, ventilation, state-only with no recoverable upstream cause, explicit source retention after event, missing/failed app logs and no-fresh-read requests. No new definite cause may be fabricated. For retention-limited cases, correct result is "outside retention if proven; stop app-log retries" and keep any independent native history candidates. Report the answerable output event and what missing source would discriminate the unresolved cause.

**Live gate (not passed by CI):** uncoached first answers for heating plus lighting/ventilation with *original* private Technical JSON; score factual grounding, source completeness, causal calibration, usefulness, source-selection precision, rank and actual useful-read rate, token use, model rounds and elapsed time. Confirm the model independently chooses an effective read, retention remains truthful, native writes are absent, and end-to-end causal explanation comes from returned evidence. Exact-head CI must be green; any high-cost model-loop regression, repeated empty broad logs, wrongful app-issuer attribution or false definite cause is a release-blocking live result. No specific heating TRV is hardcoded.
