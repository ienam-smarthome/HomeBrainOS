# HomeBrainOS V2 alpha.121 — natural local event times and preserved later observations

**15 November 2026. V2 Preview only.** This public engineering note does not reproduce private home sources or credentials. All regression fixtures use fictional devices.

## Original installed alpha.120 first-answer review

The owner asked when a light last changed from ON to OFF during a 12-hour window and why. The successful original current-request MCP receipts comprised **one filtered inventory** and **one switch-attribute event history**: 11 event rows, reported source lookback 12 hours, row limit 100 not reached, earliest returned switch at 18:19, latest returned at 21:49. The latest observed ON/OFF pair was ON at 21:07:38 to OFF at 21:48:21, followed by another ON at 21:49:47. The original inventory reported ON and level 60, but no separate `hub_get_device` was executed in this request. The bridge reported the OFF state; the `triggered[]` applications were event listeners, not proven command initiators. There were **zero source errors, zero monitor reads and no original execution-specific causal record**. The source does not verify why the OFF occurred or complete 12-hour history. Earlier draft assertions citing a native `hub_get_device` in this request and claiming large current-request truncation were not supported by the two original receipts; they did not survive typed publication.

The installed alpha.120 answer correctly identified the observed pair and avoided invented causes, but published raw ISO offset timestamps, dropped the later ON and the native inventory snapshot, and called the focal transition “unobserved” when the reports were observed but the *cause* was unknown. Human review: grounding 2/2, completeness 1/2, causal calibration 2/2, usefulness 1/2 = 6/8. The server spent 36.4s in 4 model rounds with 171,850 reported input tokens; the 78.9s client elapsed duration is not explained by provider/server timings. This single run is not a p95 or controlled efficiency comparison.

## General alpha.121 correction

- **Publication only** for already eligible natural-language “when did [device] last change from A to B” questions: format exact source-offset-aware instants as natural **weekday, day month year, 12-hour clock and timezone abbreviation**. Example: “Sunday 15 November 2026 at 9:48 pm GMT”, not raw ISO. Resolve the hub's configured **IANA timezone** via `zoneinfo`, including BST/GMT and repeated autumn wall times. If a valid timezone is not configured, label the UTC conversion explicitly. Never guess an offset for naïve input, invent an observation, or interpret a wall time as a command deadline.
- Preserve the exact original ISO **pair timestamps in PRIVATE `temporal_transition_verification` metadata**, plus unchanged original native receipts. Human-readable minute-level presentation does not alter ordering/precision of source evidence or model-selected tools.
- Preserve a later returned state report (if present) and a strictly matching source-reported inventory snapshot. Neither claims a current physical outcome or missing historical events. Include an allowlisted reported-by name as the **reporter**, not a unique initiator. Do not replace unknown cause with a specific automation theory.
- Retain alpha.119–120 focal before/after verification, row cap/truncation qualifications, matching focal lookback, read-only native tools and original UI write approval checks. No new native read, model round, source router, historical polling, cost setting or V1 change.
