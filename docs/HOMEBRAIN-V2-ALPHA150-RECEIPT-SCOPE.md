# V2 alpha.150 receipt scope and prospective acceptance

Alpha.149 did not pass the source-real quality gate. Cases 05–07 and 10
published unsupported continuity, event-store absence, or log retention
claims. Alpha.150 extends the existing conservative read-only publication
check for those claim forms. Fallback keeps the latest returned health state
and the corresponding inventory activity timestamp, bound to the same native
device ID. An inventory timestamp does not identify its updater or establish
device reachability. The check adds no extra model rounds, native calls, or
write permissions. Its coverage is limited to recognised categorical forms.

On installed alpha.150, configure a dedicated Read ON / Write OFF client.
Open **Acceptance study**, enter the eight exact private labels, and seal
`alpha150-prospective-v1`. Capture cases `a150-01` through `a150-10` once and
run offline verification. Use the same independent source grading and
promotion thresholds as for alpha.149. Previous cohorts remain separate.
No live alpha.150 capture or quality result is claimed.
