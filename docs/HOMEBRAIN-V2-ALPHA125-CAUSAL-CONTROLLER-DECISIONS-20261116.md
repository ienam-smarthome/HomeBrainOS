## General architecture

- New `causal_decision_frontier.py` examines ONLY the original current-request successful MCP device-event receipts to find **recorded command** rows and their original `producedBy.appId`, exact timestamp and event name. State reporters and `triggered[]` listeners are deliberately excluded from the issuer set. It scans bounded returned rows and records app-scoped original log/execution read **attempts** and **successes** separately from app configuration reads. Reading a log is not proof the app executed the claimed branch; an unattempted log is not proof of unavailable logs.
- When a read-only causal inquiry has an identified app-command issuer but no app-scoped execution read, prepend a compact controller-decision checkpoint during the **existing source-review model round**. The model, not the host, decides whether a focused native READ-ONLY app-log/decision-input history read is offered, feasible and useful. The host does not force any app, tool, query, device, timing window or source order; it does not add a new model round or write. Explicit no-new-read and action boundaries are respected.
- Existing general source/system guidance distinguishes issuer, runtime decision input, reported state and physical operation. It warns against old temperatures as the causal input, modern configuration as historic execution proof, unsupported “no other command” exclusivity and chronologically reversing command vs attribute rows.
- PRIVATE Technical JSON includes `causal_controller_decision_frontier` to make source-type coverage and identifiable issuer visible to reviewers, without copying raw app logs or credentials. Full original receipts are preserved untouched. No changes to the stored runtime controller or its hysteresis/delay/protection policies.
